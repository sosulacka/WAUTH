# WAUTH

Плагин авторизации для серверов Minecraft на базе Paper/Purpur. Закрывает регистрацию и вход по паролю, поддерживает двухфакторную аутентификацию через мессенджеры и предоставляет веб-интерфейс для привязки второго фактора.

Версия: 0.0.5
API: 1.21
Java: 21

## Возможности

- Регистрация и вход по паролю. Пароли хранятся в виде bcrypt-хэшей, открытый текст на диск не попадает.
- Двухфакторная аутентификация с одноразовыми кодами и резервными кодами восстановления.
- Привязка второго фактора через Telegram, VK и Discord, а также через веб-страницу. Все боты работают внутри плагина, без внешних сервисов.
- Веб-сервис на встроенном HTTP-слое с мультиплексированием порта: интерфейс отдаётся на том же порту, что и игровой трафик, без отдельного открытого порта.
- Опциональный туннель через cloudflared для доступа к странице привязки без ручной настройки проброса портов.
- Хранилище на SQLite с атомарной записью файлов и шифрованием чувствительных данных.
- Ограничение числа попыток входа и фильтрация паролей из консольных логов.
- Административные команды для смены и сброса паролей игроков.
- Полноценное управление своим аккаунтом из привязанного Telegram, VK или Discord: статус, блокировка/разблокировка и смена пароля с подтверждением.
- В уведомлении входа показывается фактический IP подключения. Запрос закрывается и удаляется после обработки, где это позволяет API мессенджера.
- Совместимость со старыми форматами данных и автоматическое обновление конфигурации с сохранением существующих значений.

## Требования

- Сервер Paper или Purpur версии 1.21.
- Java 21 в среде выполнения.
- Folia не поддерживается.

## Установка

1. Соберите или скачайте `WAUTH-0.0.5.jar`.
2. Поместите файл в каталог `plugins` сервера.
3. Запустите сервер один раз, чтобы сгенерировать `plugins/WAUTH/config.yml`.
4. Отредактируйте конфигурацию под свои задачи и выполните `/wauth reload` или перезапустите сервер.

## Команды

| Команда | Назначение | Доступ |
| --- | --- | --- |
| `/register <пароль> <подтверждение>` | Регистрация нового аккаунта. Псевдоним `/reg`. | все |
| `/login <пароль>` | Вход в аккаунт. Псевдоним `/l`. | все |
| `/changepass <текущий> <новый>` | Смена собственного пароля. | `wauth.changepass` |
| `/forcechangepass <ник> <новый>` | Принудительная смена пароля игрока. | `wauth.forcechangepass` |
| `/forceresetpass <ник>` | Сброс пароля и сессии игрока. | `wauth.forceresetpass` |
| `/2fa <link\|status\|enable\|disable\|unlink\|code>` | Управление двухфакторной аутентификацией. | `wauth.2fa.use` |
| `/wauth <confirm\|reload>` | Служебные команды. Псевдоним `/wa`. | оператор |

### Управление через бота

После привязки отправьте боту `/start` или `/status`. Команды `/lock` (синоним `/ban`), `/unlock` и `/password <текущий> <новый>` доступны только владельцу привязки и всегда требуют отдельной кнопки подтверждения. Пароли обрабатываются в ограниченной очереди, сообщения удаляются Telegram/VK при наличии прав, а Discord использует защищённую форму. При подозрительном входе отклоните запрос, заблокируйте аккаунт и смените пароль.

## Права доступа

| Право | Описание | По умолчанию |
| --- | --- | --- |
| `wauth.changepass` | Смена своего пароля. | включено |
| `wauth.forcechangepass` | Смена пароля другим игрокам. | оператор |
| `wauth.forceresetpass` | Сброс пароля другим игрокам. | оператор |
| `wauth.reload` | Перезагрузка конфигурации. | оператор |
| `wauth.2fa.use` | Использование двухфакторной аутентификации. | включено |
| `wauth.2fa.required` | Обязательная привязка 2FA для входа. | выключено |
| `wauth.2fa.admin` | Администрирование 2FA. | оператор |
| `wauth.admin` | Полный доступ к администрированию. Включает права выше. | оператор |

## Двухфакторная аутентификация

Второй фактор привязывается через мессенджер или веб-страницу. Игрок запрашивает привязку командой `/2fa link`, получает ссылку или код, подтверждает его на стороне мессенджера и в игре. При включённом втором факторе вход требует одноразового кода; коды восстановления выдаются один раз и показываются только после подтверждения игроком, что они сохранены.

Веб-страница отдаётся встроенным HTTP-сервисом на игровом порту. При необходимости внешнего доступа можно включить туннель через cloudflared. Страница не подключает сторонние скрипты, шрифты и аналитику; ответы отдаются с заголовками no-store, CSP, запретом фреймов и nosniff.

## Конфигурация

Файл `config.yml` создаётся при первом запуске в `plugins/WAUTH`. Он содержит настройки хранилища, ограничений входа, веб-сервиса, туннеля и провайдеров второго фактора. Изменения применяются командой `/wauth reload`. Если разбор конфигурации завершился ошибкой, предыдущая рабочая конфигурация сохраняется, а не заменяется значениями по умолчанию.

## Сборка из исходников

Проект собирается через Gradle с использованием shadow-плагина.

```bash
./gradlew build
```

Готовый артефакт появится в `build/libs/WAUTH-0.0.5.jar`. Прогон тестов:

```bash
./gradlew test
```

## Хранение данных и безопасность

- Пароли и данные второго фактора хранятся в зашифрованном виде, ключ шифрования не заменяется автоматически при повреждении.
- Ошибки чтения баз данных прерывают инициализацию и блокируют вход, чтобы исключить повторную регистрацию существующего аккаунта или отключение второго фактора.
- Токены подтверждения привязаны к UUID игрока и очищаются при отключении.
- Пароли и коды не попадают в консольные логи.
